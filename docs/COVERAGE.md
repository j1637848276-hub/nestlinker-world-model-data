# 数据覆盖与缺口（2026-09-14）

这个仓库采用“广目录、严准入”：先记录对外国租客决策可能有用的公开数据入口，再只把许可、隐私、时间口径和来源链都能解释的数据放进快照。它是持续扩展的登记册，不声称已经穷尽整个互联网。

## 已登记

- 34 个数据源，覆盖 12 类：市场、人口、房产风险、保证金风险、交通、地理、法律、住房供给、住房质量、教育、环境和生活设施。
- 31 个来源是韩国政府、公共机构或官方法律/指南；1 个 CC0 社区站点坐标只作原型，并明确要求上线前用运营方数据复核。
- 访问方式被分为 API key、公开下载、链接版本化和人工许可审查。

## 重要缺口

新增 `seoul-rental-history-2026-09-14`：2011–2024 的 6,139,058 条源行，经明确的同年度价格视图筛选及隐私抑制后，发布 32,085 个区月聚合组，代表 5,569,590 条来源行。旧快照保持不变，新旧覆盖重叠，不能相加为独立成交量；迟报不是无效数据，但不在这一保守回放视图内。详细守恒与真实采集状态见 [本轮报告](research/data-pipeline-status-2026-09-14.md)。

1. 没有合法可再发布的实时房源库存，因此不能做“今天有哪些房”的平台式承诺。
2. 建筑台账、中介注册、HUG 风险、大学、官方铁路和环境数据目前只有来源契约，尚未形成版本化快照；需要 API key 或按来源许可逐项下载。
3. 押金优先权、登记簿权利关系和保证资格具有合同当时性，最终必须引导用户查官方文件或专业人员，不能由统计模型代替。
4. “语言服务”“拒租经历”“隐藏费用”“沟通摩擦”等外国租客痛点没有可靠公共结构化数据，后续只能通过知情同意、最小化采集的用户旅程事件补齐，并与现实事实层隔离。
5. 对法律、开放接口和许可条款必须定期复查；目录中的链接存在更新或退役风险。

## 下一批采集顺序

1. 真实用户的合同核验、押金返还/延迟/损失与找房过程结果；必须知情同意、最小化并保存在受控后端，不能提交 Git。
2. HUG 保证事故、保证发行与余额的年度序列，用于总体背景和教育，不能映射成个体房源风险。
3. 行政标准代码、官方铁路/站点、大学和首尔外国人统计。
4. 建筑 HUB 与持牌中介注册，只保留决策所需字段。
5. 首尔易涝区、AirKorea 与必要生活设施；只做可解释上下文，不合成为“安全分”。

# 首尔年度租赁审计操作说明

本工具是历史回填的第一道诊断步骤。它不会删除重复记录、修改原始文件、生成正式快照或批准数据入库。

## 获取原始文件

在仓库根目录运行（Python 3.9+，仅使用标准库）：

```powershell
python scripts/download_seoul_history.py --output-dir data/raw/seoul-rental-files/<新的批次名>
```

默认下载 2011–2025。可用 `--years 2022 2023 2024` 选择年份。脚本从官方页面解析年度文件编号，使用页面的下载表单接口。官方页面要求按 `접수년도`（受理年度）筛选，但年度 ZIP 的实际内容并不始终符合单一口径；台账因此称为 `file_year`，并要求逐行审计合同年和受理年。每个批次必须是新目录，保存来源页面、原始 ZIP 和 `acquisition-ledger.json`，记录抓取时间、字节数、下载地址及 SHA-256。失败响应保留为 `.partial`，不会当成 ZIP 使用；失败后用新批次重试所需年份。

`data/raw/` 和 `data/work/` 已被 Git 忽略。不要把原始物业记录、异常记录或未审阅的细分诊断报告提交公开 Git。

## 审计

```powershell
python -m worldmodel_data audit-seoul-history --raw-dir data/raw/seoul-rental-files/<批次名> --acquisition-ledger data/acquisitions/<批次名>/seoul-rental-files.json --output-dir data/work/seoul-history-audit/<新的运行名>
```

默认逐年审计 2011–2025。可指定 `--years`，以及 `--duplicate-threshold 0.01`。阈值沿用旧聚合器的 1%，是审查触发规则，不是证明重复无害的统计阈值。正式审计应传入下载台账；原始文件与台账中的 SHA-256 或字节数不一致、台账缺少年份时，文件进入隔离。报告目录不可覆盖，也不能位于原始输入目录内。中断运行会留下已经完成的年度报告；新运行使用新目录。

输出：

- `<year>.audit.json`：原始哈希、ZIP 成员、编码、分隔符、原始列名和 schema 哈希；空值、非法字段、金额范围、合同年/受理年交叉分布、月份/地区/用途/租赁类型数量；精确重复组的次数分布、重复集中月份和地区、常见行间距。
- `summary.json`：完整汇总、相邻文件的精确字段组重叠、字段增删、年度总行数比、审计代码哈希和规则版本。
- `SUMMARY.md`：中文入口表格。

支持单个 CSV 或 TXT 成员，UTF-8（有/无 BOM）、UTF-16 BOM、CP949，以及逗号、制表符、分号和竖线分隔。只有匹配已知韩文字段名的字段才参与语义检查，不能识别的 schema 明确要求适配，绝不猜测金额单位或填造受理年份。

状态：

| 状态 | 含义 |
| --- | --- |
| `missing` | 对应年度 ZIP 不存在 |
| `quarantined` | 文件无法完整读取、为空，或精确重复率超阈值 |
| `requires_adapter` | 文件可读取，但缺少当前语义检查所需字段；必须增加显式 schema 适配器 |
| `needs_review` | 存在字段、年份或覆盖异常，需要逐项解释 |
| `checks_passed_pending_review` | 已实现检查未发现异常，仍须审阅来源和覆盖 |

退出码 0 表示报告已完成且没有缺失/隔离年度（仍可能有 `needs_review`）；2 表示报告已生成，但有缺失或隔离年度；其他非零结果表示运行错误。判断入库资格不能只看退出码。

## 如何解读与后续回填

`accounting` 是互斥计数：无效字段优先，其次合同年份不同于文件年份、受理年份不同于合同年份，最后是旧回放规则可接受行。四项之和等于已读取行数。`other_contract_year` 本身不等于错误；它通常表示迟报或历史合同在后续年度受理，少量未来合同日期需要作为异常调查。文件名、合同年和受理年三者都要保留，不能用其中一个覆盖另一个。`issue_row_counts` 可以重叠，不能相加当成删除数量。重复计数独立于这笔账，所有行都仍在原始 ZIP 中。

重复以解析后的**全部字段值**相等为标准，保留空白和字段内容，哈希索引不包含明文物业数据。重复的交易含义仍未知；跨年度比较只识别完整字段集合一致的情况，不能识别修订过字段的同一合同。相同组出现多次、固定行距都只是线索。

金额极值、缺月、缺区和年度数量变化提供人工复核依据，工具不因极端值自动删行，也不声称已识别所有异常。区代码校验使用当前首尔 25 区代码集合；若历史代码不同，需要有官方依据的有效期映射后再处理。

处理顺序：复核 2022–2024 与原报告一致性；检查 2011–2021 TXT 格式及覆盖差异；为格式变化添加显式适配器与测试；2025 对比下载哈希与原隔离证据、调查重复模式，未解释前维持隔离。进入下一阶段才修改标准化/发布管道。迟报记录应保留在受控数据层，回放筛选与原始保存分开。

审计报告含细分数量和金额极值，默认留在 `data/work/`。正式发布聚合仍应执行原有小样本抑制和 manifest 门禁。
